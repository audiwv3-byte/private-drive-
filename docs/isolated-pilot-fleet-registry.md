# PRIVATE DRIVE — изолированный реестр пилотов для автоматической диспетчеризации

**Статус:** только тестовый код ветки `feature/flutter-independent-auth`. Не подключён к Flutter, HTTP, действующим заказам, Render, PythonAnywhere, Telegram, SMS или платежам.

## Подготовлено

- `pd_fleet_registry.py`: собственная SQLite-схема синтетических учётных записей с ролями `pilot / dispatcher / passenger`. Тестовые учётные записи регистрируются только прямым вызовом `seed_synthetic_identity` из доверенного тестового кода; **нет** публичного HTTP-метода выдачи ролей.
- Запись пилота: одобрение диспетчером, статус на линии, готовность автомобиля, занятость, валидированные GPS-координаты и временная метка GPS.
- GPS старше **90 секунд**, GPS с будущей временной меткой, неопределённые координаты, пилот без одобрения, офлайн/занятый пилот и неподготовленный автомобиль исключаются.
- Список кандидатов формируется только по доверенным дорожным ETA, переданным серверным адаптером; координаты по прямой и искусственная скорость для ранжирования не применяются. При отсутствии маршрута кандидат не попадает в список.
- `offer_nearest_synthetic` передаёт допустимые кандидатуры существующему изолированному `pd_auto_dispatch.py`, где **3** предложения создаются одновременно на **20 секунд**, а один заказ может выиграть только один пилот.
- `test_fleet_registry.py`: тесты фильтрации, ранжирования, прав ролей, просрочки GPS, отзыва одобрения, ошибок координат/ETA и группового предложения.
- Ручной действующий диспетчерский API `pd_pilot_dispatch.py` и старая тестовая ручная схема `pd_demo_server.py` **не менялись**.

## Важные ограничения до настоящего включения

1. Синтетическая роль `authenticated_dispatcher` и `authenticated_pilot` — это **аргументы доверенного тестового адаптера**, а не проверка настоящей HTTP-сессии. В production потребуется авторизация по серверному access token и проверка роли в БД на каждом запросе.
2. Нет фоновой доставки push / websocket / polling групповых уведомлений трём настоящим пилотам.
3. Проверка доступности при **выборе** кандидатов пока идёт отдельной транзакцией до транзакции отправки предложения. В реальном сервисе требуется повторная проверка свежести GPS, онлайн-статуса, занятости и действительности автомобиля **в транзакции выдачи и принятия** предложения.
4. Резервирование одной машины/пилота между **разными заказами** ещё не реализовано: нужны ограничения БД и атомарное занесение занятости вместе с закреплением заказа.
5. В репозитории нет готового доказанного многопилотного GPS-бэкенда с безопасным разграничением видимости личных данных и контролем частоты.
6. Передача координат, оценка ETA по дороге и платная дальняя подача должны согласовываться с пассажиром и обработкой конфиденциальности; тарифы не должны автоматически инициировать списания.
7. В случае нехватки трёх пилотов допустима меньшая группа; повторные раунды исключают предыдущих адресатов. При отсутствии доступных пилотов заказ должен оставаться у диспетчера, без фиктивного «водитель найден».
8. Деплой Render не выполнялся. Рабочее пространство Render не выбрано — нельзя самостоятельно назначать его без подтверждения владельца.

**Режим автоподбора пока не включён.** Использовать синтетические тестовые идентификаторы и отдельную тестовую БД.
