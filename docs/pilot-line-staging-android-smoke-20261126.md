## Предварительные условия (не считать выполненными без проверки)

1. GitHub Actions `45732407826` или более поздний CI **завершился success** для проверяемого SHA; jobs `assignment-postgres` и `build-android-release` зелёные.
2. В GitHub Actions доступен APK ZIP-артефакт. Извлечь `private-drive-qa.apk`, `SHA256SUMS`, `APK_BADGING.txt` **из одного и того же артефакта**. Выполнить `sha256sum -c SHA256SUMS`; проверить package `lt.privatedrive.private_drive.pilot`, label `PRIVATE DRIVE`, подпись `apksigner verify`, ненулевой размер APK и целостность ZIP. Не сообщать SHA-256 без чтения фактического файла.
3. APK собирается с `PD_NATIVE_PILOT_ASSIGNMENT=true`, `PD_QUICK_RESUME=true` и staging auth host `https://private-drive-drbd.onrender.com`. Не выдавать внутренний `.pilot` APK за финальное обновление существующего package ID.
4. На **staging**, а не на production, отдельно проверено наличие смонтированного маршрута `GET/PATCH /native-pilot-availability` и миграции `pd_native_pilot_availability`, а также общей изолированной базы с веб-диспетчерской. Если маршрут возвращает 404/503 или недоступен — STOP, только staging-деплой после отдельного явного разрешения. Отсутствие доступа к серверу не заменять подстановкой клиента.
5. Для теста используются проверенный пилот с действующим решением по фотографии и действующей сессией; диспетчер с разрешёнными правами; одна тестовая заявка. Данные и токены в отчёте редактировать/маскировать.

## Сквозные Android-сценарии

| № | Шаг | Ожидаемый серверный результат |
|---|---|---|
| 1 | Войти пилотом, открыть брендированную «КАБИНУ ПИЛОТА» | Фон Вильнюса, логотип, серверные заказы, «НЕ НА ЛИНИИ»; никакого локального демо-статуса |
| 2 | Открыть диспетчерский список пилотов **до** выхода | Пилот отсутствует в `/dispatch/orders/eligible-pilots` |
| 3 | Нажать «ВЫЙТИ НА ЛИНИЮ» | `PATCH /native-pilot-availability {"online":true}`, только серверный ответ меняет надпись на «НА ЛИНИИ» |
| 4 | Повторно открыть список диспетчера | Пилот появился, только если фотодопуск ещё действителен |
| 5 | Через 45 секунд при открытой кабине | Клиент посылает новое подтверждение `online=true`; `changed_at` обновлён на сервере |
| 6 | Нажать «УЙТИ С ЛИНИИ» | `PATCH {"online":false}`; диспетчер больше не показывает пилота и не позволяет назначить новую заявку |
| 7 | Отсоединить сеть, повторить включение/выключение | Приложение не утверждает недоказанный статус: «СТАТУС НЕИЗВЕСТЕН» и предлагает повторную проверку; никаких локальных подтверждений |
| 8 | Возобновить сеть, повторить проверку | Отображается фактический статус сервера |
| 9 | Выйти на линию и закрыть приложение/прервать связь более чем на 120 сек | Кандидат автоматически исчезает из списка и новая заявка не назначается. Без симуляции фонового GPS |
| 10 | Запустить приложение снова | Повторная авторизованная проверка доступности; для возврата на линию требуется новое подтверждение |
| 11 | Перейти к карте и обратно | Карта не подменяет серверную доступность; нет фиктивных точек GPS |
| 12 | Повторить с неподтверждённой/просроченной фотографией | Сервер отвергает `online=true`; никакого допуска в диспетчерской |

**Отдельно:** назначенный до потери связи заказ не удалять; проверять его статус на сервере. Снятие пилота с линии означает только запрет новых назначений, не удаление поездки.
