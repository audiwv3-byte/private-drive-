# PRIVATE DRIVE — локальный Safari-стенд регистрации (НЕ публиковать)

Это отдельный тестовый шлюз. Он **не запускается автоматически**, не меняет Netlify,
PythonAnywhere, DNS сайта `privatedrive.lt`, Flutter, Telegram и боевые API.
Сервер регистрации `pd_test_registration.py` остаётся в памяти процесса,
не принимает запросы напрямую из сети и не отправляет SMS/email.

## Модель угроз и границы доступа

- Запуск возможен только после явного вызова `serve_private_tls(...)`.
- Шлюз привязывается **только к выбранному частному IPv4 компьютера** (RFC1918), никогда к `0.0.0.0`.
- **Только один разрешённый IP iPhone** может открыть страницу.
- Требуются TLS-сертификат с SAN `DNS:pd-test.local`, ключ на локальном компьютере,
  доверие к локальному CA на iPhone, пароль минимум 20 символов и HTTP Basic поверх HTTPS.
- Запрос POST требует Origin того же HTTPS-хоста и заголовок `X-PD-Test: 1`; CORS не включается.
- Разрешены только `/registration.html`, `/registration-client.mjs`,
  `/private-test-bootstrap.js` и два test-registration POST эндпоинта.
- Допустимы **только вымышленные адреса `@example.test`**. Не вводи личный email, телефон или имя.
- Тестовый OTP доступен только через терминал компьютера по команде `code ...`.
- В браузер не возвращаются `access_token` и `destination`.
- Выбор пилота создаёт состояние `pending`; доступ к поездкам не предоставляется.
- После `stop` база и коды в памяти теряются.

**Ограничение:** IP-ограничение и HTTP Basic не заменяют доверенный Wi-Fi.
Не включай проброс портов, публичные туннели, облачные прокси, общий гостевой Wi-Fi.
Файлы сертификатов и пароль никогда не добавляй в GitHub.

## Подготовка на локальном компьютере

1. Компьютер и iPhone подключи к одной **доверенной** Wi-Fi сети; узнай их частные IP,
   например компьютер `192.168.1.10`, iPhone `192.168.1.50`.
2. Обеспечь локальное разрешение `pd-test.local` в частный IP компьютера,
   например локальным DNS или mDNS. **Не меняй публичные DNS** для `privatedrive.lt`.
   Просто запись в hosts компьютера не обеспечивает разрешение имени на iPhone.
3. Создай локальный TLS-сертификат для `pd-test.local` через `mkcert` или собственный CA.
   Перед работой в Safari нужно установить и явно доверить корневой сертификат CA на iPhone
   (Settings → General → About → Certificate Trust Settings). Проверяй SAN и HTTPS.
   Если нет доверенного сертификата или локального разрешения имени — **не запускай тест**.
4. Храни сертификат и ключ вне репозитория. Сгенерируй случайный пароль минимум 20 символов,
   не вставляй его в исходники и не отправляй в чат.
5. В локальном терминале Python импортируй `serve_private_tls` и вызови:

```python
from pd_private_safari_gateway import serve_private_tls

serve_private_tls(
    bind_ip="192.168.1.10",       # заменить на локальный IP компьютера
    iphone_ip="192.168.1.50",     # заменить на локальный IP iPhone
    password="SET_A_NEW_RANDOM_SECRET_OF_AT_LEAST_20_CHARS",
    certfile="/private/path/pd-test.local.pem",
    keyfile="/private/path/pd-test.local-key.pem",
    port=8443,
)
```

Числа и пути в примере **условные**. Пароль в коде примера не используй как реальный секрет;
лучше подставить его из переменной окружения в своём локальном скрипте. Открывай в Safari
**только** `https://pd-test.local:8443/registration.html`. Браузер должен запросить имя
`pd-test` и заданный пароль.

### Проверка

- Заполни только вымышленные `Test Passenger` / `passenger@example.test`.
- Нажми «Запросить тестовый код». В терминале компьютера введи `code passenger@example.test`.
- Введи показанный в терминале шестизначный код в Safari. Повторить с
  `Test Pilot` / `pilot@example.test` и `code pilot@example.test`.
- Убедись, что неверный OTP отклоняется, а пилот остаётся в ожидании одобрения.
- В терминале введи `stop` — сервер остановится, содержимое памяти будет утрачено.
