# PRIVATE DRIVE — зашифрованная резервная копия PostgreSQL (подготовка)

Статус: **не запускалось**. В этом документе нет URL базы, SMS, паролей, номеров телефонов или приватного ключа.

## Что уже готово
- Изолированная база: Render `private-drive-test-db` (Frankfurt, план Free, срок до 2026-12-20).
- Скрипт `ops/private_drive_encrypted_pg_backup.py` экспортирует **только** базу `private_drive_test`.
- Поток `pg_dump -Fc` передаётся непосредственно в `age`; обычный дамп на диск не создаётся.
- Скрипт требует `PD_DISPATCH_STAGING_ONLY=1`, отдельное разрешение, публичный ключ age, явный путь к архиву и TLS-подключение.
- В CI запускаются только безопасные тесты ограничений, без подключения к личным данным.

## Схема хранения
1. На доверенном Windows-ноутбуке создать ключевую пару age. Закрытый ключ хранить **вне** папки, синхронизируемой с облаком; сохранить отдельную аварийную копию ключа офлайн.
2. Зашифрованный файл вида `private-drive-test-YYYYMMDD.age` положить в локальную папку `Documents/PRIVATE-DRIVE/Backups`, исключив из индексации общедоступных папок и GitHub.
3. Скопировать **только файл .age** в отдельное облачное хранилище, включив 2FA. Не загружать туда закрытый ключ, исходный дамп, файл .env или пароль к базе.
4. Проверить совпадение SHA-256 двух архивов и выполнить пробное восстановление **в другую пустую временную базу** перед любой миграцией. Не проводить восстановление поверх существующей PostgreSQL.
5. После успешной проверки и отдельного разрешения можно рассматривать миграцию. Встроенных бесплатных PITR-бэкапов у Render Free нет.

## Безопасность и ограничения
- Прямой экспорт с ноутбука использует **External Database URL**, доступный только авторизованному владельцу Render, а не Internal URL (последний предназначен для внутренней сети Render).
- URL и пароль не пересылать в чат, не вставлять в GitHub Secrets без явной необходимости.
- Бесплатная база истекает 2026-12-20: это не постоянное хранилище для реальных документов и заказов.
- Даже зашифрованный архив содержит персональные данные; установить правила доступа, срока хранения и удаления согласно GDPR.
- Пока ключи, внешний URL, место хранения и тест восстановления не подтверждены, **не запускать экспорт и миграцию**.
