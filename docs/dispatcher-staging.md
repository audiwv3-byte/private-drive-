# PRIVATE DRIVE — изолированная тестовая диспетчерская

## Что готово
- /dispatch/login — браузерная форма входа
- /dispatch — пустой кабинет без заказов и персональных данных
- /dispatch/logout — выход с защитой CSRF
- /dispatch по умолчанию возвращает HTTP 503 до настройки окружения
- Авторизация существующего Telegram Mini App не изменена

## Запуск только в отдельной тестовой среде
Никогда не добавляй ключи или пароли в GitHub. Используй отдельные тестовые переменные:

- PD_DISPATCH_SESSION_SECRET — случайный секрет от 32 символов (отдельно от Telegram)
- PD_DISPATCH_PASSWORD_HASH — результат werkzeug.security.generate_password_hash для уникального тестового пароля
- PD_DISPATCH_ADMIN_ID — числовой ID администратора, присутствующий в *тестовой* конфигурации ADMIN_IDS

Запускать за HTTPS (cookie Secure). Не использовать производственные базы, ключи, Telegram-токены и платёжные провайдеры.

## Проверка
```bash
python -m pip install 'Flask==3.0.3' 'Werkzeug==3.1.9'
python -m unittest -v test_web_dispatcher.py
```

Проверки: режим по умолчанию закрыт, вход требует CSRF и пароль, неверная роль не допускается, после выхода доступ закрыт, используются Secure/HttpOnly/SameSite cookies.

Тесты могут запускаться из workflow `.github/workflows/dispatcher-auth-test.yml`.
Наличие файла workflow **не подтверждает успешный прогон**: нужно проверить завершённый GitHub Actions run и его лог.

## Ограничения
Это минимальный прототип для одной тестовой административной учётной записи, а не готовая многооператорная система. До публичного запуска необходимы: проверка устойчивого хранилища блокировок входа, ротация сессий/секретов, раздельные роли диспетчеров, HTTPS и проверенный независимый staging-деплой. Никакого доступа к рабочим заказам прототип не даёт.
