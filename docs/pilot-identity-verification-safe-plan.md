# PRIVATE DRIVE — план безопасной проверки личности пилота (проект, без включения)

Ветка: `feature/flutter-independent-auth`. Статус: **только проектирование**, не разрешение на обработку реальных фотографий.

## Аудит текущей реализации, 21.11.2026

- `flutter_app/lib/pilot_identity_check_page.dart`: только `Permission.camera.request()`, никаких кадров, видео, отправки, хранения, сравнения лиц и изменения прав пилота.
- `flutter_app/lib/camera_test_main.dart`: автономный экран камеры без аккаунта, SMS, поездок и администраторских прав.
- `flutter_app/test/pilot_identity_check_page_test.dart`: проверяет запрос по нажатию и сохранение статуса «не проверено».
- `test_sync_server/pd_identity_check_policy.py`: чистая функция, требуется повторная проверка при отсутствии подтверждения, будущем времени, ошибочном значении или сроке >=7 дней. Не подключена к настоящим правам.
- `miniapp/templates/driver_privacy_ru.html`: описывает будущую проверку, но не объявляет её действующей; конкретные сроки удаления и условия обработки ещё не установлены.
- Реального защищённого API загрузки, объектного хранилища, схемы заявок, ACL для проверяющего, удалителя фотографий и процесса апелляции **нет**.

## Целевой сценарий (последовательные независимые этапы)

1. **Правовая проверка до сбора данных**. Документировать цель (подтвердить, что поездку выполняет одобренный пилот), необходимость, соразмерность, альтернативу без съёмки, прозрачное уведомление, законное основание по ст. 6 GDPR и, если используется автоматическая биометрическая идентификация, отдельное условие ст. 9. Не считать галочку достаточным правовым основанием. Оценить необходимость DPIA по ст. 35. Назначить контролёра, обработчиков, регион хранения, правила договоров, передачи данных и реагирования на инциденты. Решение о запуске — только после утверждения.
2. **Раздельные согласия и уведомления**. В экране показать цель, какие данные собираются, кто их видит, сроки удаления, последствия отказа, право обращения и альтернативную проверку. Отдельная явная кнопка «Продолжить проверку» после ознакомления; отдельный системный запрос камеры. Согласие с уведомлением не автоматически равно согласию как правовому основанию GDPR. Не использовать рекламные согласия.
3. **Съёмка на устройстве**. Только после нажатия пользователя, одна фотография лица с возможностью пересъёмки; показывать предпросмотр; не включать микрофон, видеозапись, скрытую съёмку, автоотправку или распознавание. EXIF/GPS удалять; ограничить разрешение и размер; не сохранять в публичную галерею или логи. В тестах — только синтетическое изображение.
4. **Безопасная передача**. Только авторизованный конкретный pilot_id и короткоживущий одноразовый upload token с TLS; сервер заново проверяет роль, лимит размера, MIME и содержимое файла, частоту запросов и idempotency-key. Никаких публичных ссылок, URL с токенами в логах, сторонней аналитики или Telegram-медиа. Серверная авторизация обязательна для реальной загрузки.
5. **Изолированное хранение**. Закрытый bucket вне public/webroot, шифрование при хранении, раздельные секреты, минимально необходимые метаданные, управление ключами, роли с наименьшими привилегиями, аудит просмотра/решений без копий фото. Предложение для обсуждения: исходное фото удалить через 24 часа после окончательного решения, ожидающее рассмотрения — не дольше 72 часов; отказ/апелляция — только по отдельному утверждённому регламенту. Эти периоды **не утверждены** и не являются действующими настройками. Предусмотреть удаление из бэкапов и обработку GDPR-запросов.
6. **Ручная проверка диспетчером**. Отдельное назначение reviewer для конкретного пилота; доступ к фото только на время рассмотрения, без массовых выгрузок. Сравнение с ранее подтверждённым профилем допускается только при документированном основании и законном доступе. Решения: pending / approved / rejected / needs_retry / appeal; причина и время; двусторонняя возможность исправления/апелляции. Никакого автоматического face matching.
7. **Срок 7 дней**. Авторитетный сервер хранит `last_verified_at`, `reviewer_id`, `next_due_at`; решение принимается сервером, а не телефоном. Отсутствие проверки не превращает тестового пользователя в реального пилота. При просрочке — уведомление, понятная процедура повторной проверки и ручного пересмотра; не включать блокировку новых заказов без отдельного решения и тестов.
8. **Удаление и аудит**. Периодический удалитель с журналом только идентификаторов/действий, безопасная очистка временных файлов и архивов, тест удаления без остаточных публичных URL, запрет утечки фотографий в Crashlytics/логи. Права пилота на доступ и удаление соблюдаются в рамках выбранного основания и законных исключений.
9. **Изолированные тесты**. Поддельные пилоты, изображения-макеты, mock API и локальное хранилище. Проверить запрет доступа чужого пилота, устаревшую проверку, отказ камеры, повторные запросы, превышение размера, удаление, ACL и апелляции. Запрет на отправку реальных фотографий или SMS.
10. **Отдельный gate перед включением**. Подтверждённые юридические документы и DPIA (если требуется), работающая серверная авторизация, секреты, хранение, удаление, аудиты, ручная проверка и успешные Android/iOS тесты. Только отдельное согласование после проверки.

## Первый безопасный инженерный шаг после плана

Добавить отдельный UI-экран ознакомления с целью и политикой, используя **только фиктивные данные и без кнопки реальной съёмки**, покрыть widget-тестами. Нынешнюю APK Camera Test и production не менять. Съёмку и API не включать до выполнения правовых и технических gate.
