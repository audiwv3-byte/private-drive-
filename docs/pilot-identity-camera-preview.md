# PRIVATE DRIVE — тестовый экран проверки личности пилота

**Ветка:** `feature/flutter-independent-auth`. Без развёртывания и изменения действующего приложения.

## Реализованный сценарий

1. В кабине пилота доступна кнопка **«Проверка личности · раз в 7 дней»**.
2. Экран объясняет назначение камеры, плановую периодичность и отсутствие фактического фотографирования.
3. Только после нажатия **«Разрешить камеру для проверки»** выполняется системный запрос `Permission.camera.request()` на нативных платформах.
4. При разрешении **не** запускается видеопоток, не делается снимок и не открывается доступ к микрофону. Показывается уведомление, что полноценная проверка ещё не подключена.
5. При отказе отображаются инструкции изменить настройки устройства. Нет скрытой записи, загрузки, биометрической идентификации, переключения статуса «verified» или блокировки доступа.
6. Тесты с подменённым permission-gateway проверяют отсутствие запроса до нажатия и сохранение статуса «не проверено» после любого ответа.
7. Отдельный Python-тестовый модуль ранее реализовал правило `>= 7` дней. Экран не выдаёт фальшивый результат проверки и пока не синхронизируется с ним.

## Платформенные ограничения

- iOS: `NSCameraUsageDescription` добавлен в `ios/Runner/Info.plist` исключительно для явного запроса разрешения.
- Android: исходного `flutter_app/android/` в этой ветке **нет**. Для настоящей Android-сборки потребуется воссоздание/проверка AndroidManifest с `android.permission.CAMERA` и настройкой пакета. Без этого нельзя заявлять, что системный запрос камеры на Android уже работает.
- Web/Safari: функция запроса камеры отключена; для браузера потребуется отдельное защищённое `getUserMedia`-взаимодействие, только после подтверждения пользователя.
- Микрофон не запрашивается; для будущих голосовых сообщений потребуется отдельная функция и системный запрос по действию пользователя, плюс платформенные декларации.

## До настоящей проверки

Нужно определить провайдера идентификации, безопасную загрузку и хранение фото с конкретным сроком удаления, законность обработки лица/биометрии, ручное рассмотрение спорных решений, защиту данных и реальную серверную проверку прав доступа и срока действия в момент выдачи заказа.

Не использовать UI-разрешение камеры как доказательство идентичности пилота. Ничего не сохранять в глобальную production-БД до отдельного одобрения и проверки GDPR.
